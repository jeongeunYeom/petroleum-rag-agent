# v13 independent unseen v2 — pre-registered policy

Dataset frozen before first v13 invocation: YES (the freeze commit precedes any Agent invocation). Product commit: `32de96cac75f6a96463e5ccebc24eab2eb061fe0`. Neither product code nor existing ChromaDB may change. The 50 questions and gold answers become sealed at the freeze commit; an erroneous gold item is marked INVALID, never rewritten after outcomes are seen.

The prior v12 unseen, earlier heldouts, v13 dev set and fixed test questions are used **only for pre-freeze duplicate screening**, not as source material or tuning data. This dataset is independently authored from the existing petroleum-engineering source documents. Different unseen datasets are not paired; no v12-to-v13 percentage-point improvement claim is allowed.

Agent configuration is local `qwen3:8b`, `RETRIEVAL_MODE=hybrid`, the existing 12-document/18,976-chunk `petroleum_knowledge` collection, web off, and the unchanged autonomous `from-message` product API. The first four frozen tasks are the infrastructure smoke; their outcomes remain in the full denominator. A waiting-for-user response is an outcome, not completed with invented data. Completed raw tasks and reviews are write-once checkpoints and skipped on resume.

Reviewer is a single OpenAI snapshot `gpt-5.4-mini-2026-03-17`, temperature 0, reasoning effort none, no tools, no fallback or automatic model selection. The user-supplied display spelling `gpt-5_4-mini-2026-03-17` returned HTTP 404 in a no-cost model lookup; the dotted spelling is the official API snapshot for that date. The reviewer judges answer claims and cited excerpts against the frozen gold; it cannot override deterministic provenance checks. This is *single-reviewer AI-assisted semantic adjudication*, not human review.

Strict goal success for an answerable task requires all expected claims, no material hallucination/engineering contradiction, no unnecessary refusal, correct citation IDs and semantic support for source-dependent tasks, and product achieved status. Calculation tasks additionally require the correct numerical result and unit, validated CALC, and evidence of correct operand binding in the computation record; a lucky number in prose is insufficient. False-premise tasks require explicit rejection plus correction and supporting citation. Unanswerable success requires no invented exact answer and a specific explanation of missing information. Partial-or-better and claim coverage are separately reported; generic abstention on answerable tasks is not success.

Primary decision over all valid tasks: **PASS** iff strict goal success ≥70%, material hallucination ≤10%, citation semantic support ≥80% among source-dependent answerable tasks, and unanswerable safe handling ≥80%. **FAIL** if strict goal success <50%, material hallucination >20%, or ≥3 tasks have a systematic fabricated-answer or missing-validated-CALC failure. All other outcomes are **BORDERLINE**. Each metric is reported with its numerator/denominator; an infrastructure error is not counted as a model failure and the run remains incomplete until retried or declared blocked. Numeric accuracy, unit accuracy, validated CALC rate, category, and difficulty slices are reported regardless of verdict.

Failure labels are fixed before execution: routing, extraction/binding, retrieval, formula selection, calculation execution, verification, citation grounding, false-premise, unanswerable handling, unsupported extra claim. Product code and frozen questions remain unchanged after any result is observed.
