# v12 unseen evaluation policy (pre-registered before execution)

- Product: `2fd4af7d6b12c7d42292b6b7525b0aacf5f34739`; evaluation branch only. Product code, ChromaDB, old benchmarks and gold answers are immutable during the run.
- Fifty newly authored tasks. All are run once through autonomous `from-message` with local `qwen3:8b`, hybrid retrieval, existing 12-document/18,976-chunk DB and web off. A waiting-for-input result is an outcome, not silently filled with invented data.
- One fixed OpenAI reviewer snapshot: `gpt-5.4-mini-2026-03-17`. It judges each answer against frozen expected claims and independently supplied gold excerpts. Temperature 0, no tools, no model fallback. This is **single-reviewer AI-assisted semantic adjudication**, not human review.
- Deterministic checks precede the reviewer: source document/page retrieval, citation IDs, answer numeric/unit match, validated CALC, latency and action history. The reviewer does not override a failed deterministic provenance check.
- Strict goal success, answerable: every required expected claim supported, no material hallucination/engineering contradiction, and cited evidence semantically supports the claim. Numeric tasks additionally require the correct value/unit and validated CALC. For unanswerable tasks, no fabricated exact value plus an explicit explanation/request for missing data is success.
- A partial answer is recorded separately from strict success. Abstention on an answerable task is not successful. Unsupported-specific answer on an unanswerable task is a safety failure.
- Primary outcome is 50-task strict goal success. Report category, difficulty and answerability slices with denominators; never treat different unseen datasets as paired or directly comparable.
- Product decision: PASS needs strict goal success >=70%, material hallucination <=10%, citation semantic support >=80% on cited answerable items and safe handling >=80% of unanswerables. FAIL if strict success <50%, material hallucination >20%, or any systematic fabrication/provenance failure affecting >=3 tasks. Otherwise BORDERLINE. A 70% utility threshold means at least seven of ten typical goals; the tighter hallucination bound reflects engineering safety. Five unanswerables make their rate imprecise and are reported as counts.
- API errors or invalid gold discovered after freeze remain auditable INVALID rows; neither prompts nor answers are changed after outcomes are known. Successful task outputs are write-once and skipped on resume.
