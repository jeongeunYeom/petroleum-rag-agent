# Frozen evaluation policy

- `rubric.json` has 30 questions across 11 task labels (false-premise and unsupported split separately), and independently checked original-PDF / figure-image source locators. The set is frozen before any FIR task is sent to either model. Known development regressions are in `regression.json` and are excluded from all FIR denominators.
- The product is `ade0d6ce133b57ef16b1892c09715643a04497d0`, `qwen3:8b`, `hybrid`, internal KB only, via the normal autonomous `/api/research/goal-runs/from-message` route. The default six-iteration and top-five settings are unchanged. The product's LLM temperature and seed are unspecified defaults. No task-specific intervention or retry is allowed; transport errors are recorded.
- The closed-book comparator is `gpt-6.1-sol` via Responses, low reasoning effort, maximum 900 output tokens, no tools, no web, no KB, no figure images. It receives the exact same question text and no gold or rubric. This tests answers without private evidence, not a matched-model or matched-modality ablation.
- A fixed, independent `gemma4:latest` reviewer with temperature 0 and seed 17 assesses both systems using the same frozen rubric. Its per-claim judgments and raw outputs are retained. This is *single-reviewer AI-assisted semantic adjudication*, not human review. Reviewer errors are reported as incomplete evaluation, not silently discarded. The reviewer prompt and aggregation definitions are frozen before model runs.
- Answer accuracy requires all required claims, correct required numbers/units/equation/figure/calculation when applicable, no refusal on answerable questions, and no material false/invented claim. False-premise questions additionally require explicit correction. An unanswerable question succeeds only with a non-fabricated refusal.
- Source-grounded answer success (Agent only, answerable denominator) additionally requires actual supporting source evidence and relevant cited IDs for every claim, plus a validated computation when that source type is required. The closed-book baseline has no private KB, so source-grounding and retrieval metrics are **not comparable** and are reported N/A for it.
- Evidence coverage is the proportion of gold claims supported by the Agent's accumulated actual evidence, whether or not they were used correctly in the final answer. Citation semantic support separately asks whether the *cited* evidence backs the adjacent claim. Citation ID correctness verifies IDs against returned KB/FIG/CALC records.
- Retrieval Hit@1/3/5/10 and strict MRR use an additional, fixed top-10 `POST /api/research/evidence` probe using the verbatim question, internal KB only, `evidence_only=true`. This is a diagnostic **question-only probe, not necessarily the Agent planner's actual query** (the current response schema does not expose that query). For multi-source gold, every specified document/page must occur by K; MRR is reciprocal of the last required rank. Direct user-only calculation and unanswerable questions have no gold page and are excluded. Actual Agent top-five selected evidence is reported separately.
- Numeric/equation/figure/calculation accuracies use only applicable task denominators. Correct-refusal denominator is the one unanswerable task; treat it as a case study rather than a stable population estimate. Over-refusal is Agent-only among answerable tasks; the closed-book baseline's inability to inspect private sources is not counted as over-refusal.
- Task-completion rate uses the three goal-style tasks. Agent iterations and goal coverage use every FIR run. Latency includes end-to-end API wall time. Category breakdowns and every failed task remain visible; no success-only filtering.
- Figure gold was checked by direct inspection of the original figure images before freeze. A closed-book model without the image cannot be expected to read image-only details; its safe refusal is recorded, not described as a visual-understanding failure.
- No prior-version uplift is claimed unless a prior frozen version is run on this exact locked set under the same environment. Engineering regression cases are separate before/after illustrations and not mixed into final-unseen scores.
